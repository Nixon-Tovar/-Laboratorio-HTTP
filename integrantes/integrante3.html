Lo que aprendí en el curso: servicios de la capa de aplicación

Antes tenía una idea de cómo funcionaba la red, más que todo por la parte física. En el curso aprendí que la capa de aplicación (capa 7) es la que ve el usuario: define cómo un programa, como el navegador, le pide un servicio a otro equipo y cómo le responde ese equipo. Cada servicio usa un protocolo y un puerto.

Cómo funciona HTTP

HTTP trabaja con solicitudes y respuestas. El cliente envía un mensaje con un método y una ruta, y el servidor contesta con un código de estado y el contenido.

Solicitud:   GET /index.html HTTP/1.1
             Host: localhost:8001

Respuesta:   HTTP/1.1 200 OK
             Content-Type: text/html
             (aquí viene el HTML de la página)
200 OK
La solicitud se atendió bien y el servidor devolvió el recurso.
404 Not Found
El servidor respondió, pero esa ruta no corresponde a ningún archivo.
500 Internal Server Error
El servidor tuvo un problema propio al procesar la solicitud.

También aprendí que no todas las solicitudes piden el contenido completo. GET trae la página y HEAD trae solo los encabezados, que sirve para revisar el estado de la respuesta sin descargar el HTML.

Conceptos clave

  • La capa de aplicación define el mensaje; las capas de abajo lo transportan.
  • Un servicio se identifica con un protocolo y un puerto.
  • DNS traduce nombres a direcciones IP antes de abrir la conexión.
  • HTTPS usa el mismo formato de mensajes que HTTP, pero cifrados.

Mas del lab

  1. El navegador escribe http://localhost:8001/. Como localhost es el propio equipo (127.0.0.1), no hace falta consultar un servidor DNS; con un dominio real, primero habría una consulta DNS.
  2. Se abre una conexión TCP al puerto 8001 y Docker la lleva al puerto 80 del contenedor.
  3. El navegador envía GET / y Nginx responde 200 OK con el archivo index.html.
  4. Si se pide una ruta que no existe, Nginx responde 404 Not Found.

Para ver la respuesta se puede usar curl.exe -I http://localhost:8001/ en PowerShell, o la pestaña Red (Network) del navegador con F12. En este laboratorio se usa HTTP en el puerto 80. Con HTTPS los mensajes serían los mismos, pero viajarían cifrados por el puerto 443.

Encapsulamiento

La palabra aparece de dos formas en este proyecto. Por un lado, el mensaje HTTP es el dato de la capa 7 y, al bajar por las capas, se encapsula en un segmento TCP, luego en un paquete IP, después en una trama Ethernet y finalmente en bits. Por otro lado, Docker encapsula Nginx y los archivos del sitio en un contenedor, y por eso el sitio funciona igual en cualquier sistema operativo.

Antes veía la red más que todo por la parte física: cables, señales y equipos. En el curso profundice y aprendí que por encima de eso hay una capa donde se define el mensaje que realmente pide y recibe el usuario, y que entender las capas por separado me ayuda a saber dónde buscar cuando algo falla.
