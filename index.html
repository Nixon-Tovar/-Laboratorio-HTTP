¿Qué pasa al abrir la página?

Al entrar a http://localhost:8001/, el navegador le pide la portada a un servidor que corre en la misma computadora.

  1. Navegador. Envía GET / para solicitar la portada.
  2. Docker. Publica el puerto 8001 de la computadora y dirige la conexión al puerto 80 del contenedor.
  3. Nginx. Atiende la solicitud y devuelve 200 OK con el contenido de index.html. El navegador interpreta ese HTML y muestra la página.

Compruébalo en Windows

Con Docker Desktop abierto, ejecuta estos comandos desde la carpeta del proyecto.

docker compose up -d --build
docker compose ps
curl.exe -I http://localhost:8001/

En la terminal, busca 200 OK y Content-Type: text/html. La opción -I envía una solicitud HEAD para consultar los encabezados. Al abrir la página en el navegador puedes ver la respuesta a GET en F12 → Red (Network), después de recargar.

¿Cómo veo un 404?

Con el sitio en ejecución, abre una ruta inexistente del servidor local. Nginx sigue respondiendo por HTTP, pero devuelve 404 Not Found porque esa ruta no corresponde a un archivo del sitio.

Cuatro temas del curso en una sola práctica

Modelo OSI

El modelo OSI explica la comunicación en siete capas. HTTP pertenece a la capa 7, Aplicación, donde se define cómo el navegador solicita un recurso y cómo responde el servidor. Las capas inferiores se encargan de tareas como el transporte, el direccionamiento y la transmisión de señales.

Ver las siete capas
  1. Aplicación. Protocolos de servicios como HTTP.
  2. Presentación. Representación y transformación de los datos.
  3. Sesión. Organización del diálogo entre aplicaciones.
  4. Transporte. Comunicación entre procesos de origen y destino.
  5. Red. Direccionamiento y encaminamiento entre redes.
  6. Enlace de datos. Intercambio de tramas en un enlace local.
  7. Física. Transmisión de bits como señales eléctricas, ópticas o de radio.

Modelo TCP/IP

El modelo TCP/IP agrupa la comunicación en cuatro capas. En esta práctica, HTTP define el intercambio de mensajes y TCP transporta sus datos usando una conexión al puerto publicado.

Las cuatro capas de TCP/IP
CapaFunción y ejemplos
AplicaciónIntercambio de información entre aplicaciones. Ejemplos: HTTP y DNS.
TransporteComunicación entre procesos usando puertos. Ejemplos: TCP y UDP.
InternetDireccionamiento y encaminamiento de paquetes. Ejemplos: IPv4 e IPv6.
Acceso a redEntrega sobre el enlace local. Ejemplos: Ethernet y Wi-Fi.

Topologías y cableado UTP

La topología describe cómo se conectan los equipos. En una estrella, cada equipo tiene su propio enlace hacia un switch central. Si un cable falla, el equipo conectado a ese cable pierde su enlace. Si falla el switch central, se afectan todos los que dependen de él.

Un cable Ethernet UTP tiene cuatro pares trenzados. Para armar un cable directo se puede usar T568B en ambos extremos. Un probador de cable ayuda a verificar la continuidad y el orden de los conductores.

Redes Wi-Fi

Wi-Fi conecta los equipos al punto de acceso mediante ondas de radio. En general, la banda de 2,4 GHz ofrece más alcance y suele tener más interferencia. La banda de 5 GHz suele ofrecer más capacidad a distancias cortas. WPA2 y WPA3 ayudan a proteger el enlace inalámbrico.

¿Dónde entra Wi-Fi en esta práctica? Con localhost la conexión se queda en el equipo. Si el navegador y el servidor estuvieran en equipos distintos de la misma red, la solicitud HTTP podría viajar por Wi-Fi o Ethernet según cómo estén conectados.
